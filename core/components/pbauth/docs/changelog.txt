# Changelog

## [1.1.1-pl] - 2026-10-14

### Security
 - anything a visitor typed is now printed escaped: the login, registration,
   profile, password and two-factor forms, the modal copies of them, the social
   buttons and both account e-mails. Previously a name or an address carrying
   markup was written into the page as markup
 - the profile no longer takes the avatar address from the request — the server
   decides where the file went, and the form only says whether to delete it
 - the `username` rule rejects markup characters instead of storing them

### Fixed
 - social sign-in treated an open manager session as a signed-in visitor: the
   network was linked to the administrator instead of signing the person in
 - an account joined through a social provider by a verified address stayed inactive
 - `string` was missing from the `username` rule, so length was measured as a number
 - a failed migration reported success — the resolver now checks the exit code
 - the CLI binary is looked up next to `PHP_BINDIR`, not only in PATH
 - `src/phinx.php` without `config.core.php` exited with code 0
 - the linked-networks list is assembled once, and a test checks the assembly

### Upgrading
 - nothing to do
 - accounts stuck inactive are activated on the owner's next social sign-in
 - a green installer console does not mean migrations ran — read the log
 - names already stored with markup stay as they are in the database, but are
   printed escaped from this version on

## [1.1.0-pl] - 2026-09-18

### Changed
 - routes and controllers moved into the component, registered from
   `bootstrap.php` — fixes now reach existing sites on upgrade
 - templates, form chunks, validation rules, redirects, user groups and
   controller overrides are configured in `core/App/config/pbauth.php`
   (sample in `docs/pbauth.config.example.php`)
 - install no longer overwrites files already present in `core/App/`
 - `lexicon/` is no longer copied into `core/App/`

### Added
 - sign in through Google, Yandex, Mail.ru, GitHub, Facebook and Telegram. An
   existing account is only joined when the provider vouches for the address.
   Adds the component's first table, `pba_social_accounts`
 - two-factor confirmation at login (TOTP, RFC 6238), turned on per user, with
   backup codes. Off site-wide with `'two_factor_enabled' => false`
 - `/resend-verification` — resend the confirmation link. Answers the same way
   for a known and an unknown address; rate limited per address
 - `'single_session' => true` — a new sign-in closes the previous session. The
   manager and "log in as user" are exempt
 - "log in as user" from the manager: row-menu action and a button on the user
   page. Requires a sudo session; off with `'impersonate_enabled' => false`
 - "view on the site" button, address from the `pbauth_user_page` setting
   (`{id}`, `{username}`); empty hides the button
 - events: `pbAuthUserSaving`, `pbAuthAfterRegister`, `pbAuthAfterLogin`,
   `pbAuthAfterLogout`, `pbAuthAfterProfileUpdate`, `pbAuthAfterVerifyEmail`,
   `pbAuthAfterResetPassword`, `pbAuthAfterChangePassword`. Listeners are
   registered in `App/config/pbauth.php`
 - `?redirect=` on the login form, restricted to paths inside the site
 - a page can be given its own wrapper template: a `views` key named after the
   action wins over the section one

### Fixed
 - uninstall deleted every `auth.php` and every `auth`/`Auth` folder under
   `core/App/`, including the site's own routes, lexicons and controllers. It
   now removes only what the installer recorded in
   `core/App/.pbauth-installed.json`, and only while the file is unchanged
 - the forgot-password form answered differently for known and unknown
   addresses, so it could be used to enumerate registered emails
 - `unique:modUser` / `exists:modUserProfile` never matched anything — the
   validator queries a table, not a MODX class. Now `users` / `user_attributes`
 - the "3 registrations per IP" limit counted on `modUser.ip`, a column MODX 3
   does not have. Counted in the cache now
 - `AuthController::$modxVersion` was never set, so MODX 2 processor paths were
   used on MODX 3

### Upgrading
 - requires PageBlocks 3.0 or higher
 - the package applies the migration itself; deployed by file, run
   `php core/components/pageblocks/vendor/bin/phinx migrate
   --configuration=core/components/pbauth/src/phinx.php --environment=production`
 - the upgrade deletes `App/routes/auth.php` while it is byte-identical to the
   shipped one. If you edited it, it stays and keeps working and pbAuth
   registers no routes of its own — delete it, and
   `App/Http/Controllers/Auth/`, once your changes are in
   `App/config/pbauth.php`
 - deployed by file, create the `pbAuth` plugin from
   `core/components/pbauth/plugins/pbauth.php` and attach
   `OnManagerPageBeforeRender` and `OnHandleRequest` (priority -10)
